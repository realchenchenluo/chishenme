说明

内置菜品的价格、等待时间都是全国高校的参考值，各地差异很大，请以你学校食堂和外卖 App 的实际标价为准。看到不对的，点结果卡上的「改价」，改完只影响你自己的手机。

「好吃度」是综合口碑的参考分，不是官方评分；你可以用「好吃」「踩雷」两个按钮调教它，抽签概率会跟着变。

抽签算法：先按条件硬筛，再按 口碑 × 价格 × 等待时间 × 新鲜度 加权随机。最近吃过的会明显降权，标记「别再推」的永远不会再出现。

所有数据都保存在浏览器本地（localStorage），不上传任何服务器。换手机请先「导出备份」。

参考了 GitHub 上同类项目的做法：加权抽签、重复抑制、黑名单、按预算筛选。校园菜单包的数据来源与许可写在每个包的说明里。

安全与隐私

你的数据只在这台设备上。菜单、就餐记录、黑名单、定位结果、你自己填的高德 Key，全都只写进浏览器的 localStorage。这个站没有后端、没有账号、没有统计、没有 Cookie，也没有任何第三方脚本或 CDN。

只有三个地方会联网，而且都在你点击之后才发生：定位时把坐标发给逆地理服务认城市、搜周边时发给高德（这个功能需要 Key，可选）、看券时抓取券站页面。不点就一个请求都不发。不想让坐标离开设备，就用「手动选城市」——这条路完全不联网。

坐标在上报前就会截断到小数点后三位（约 100 米精度）；导出备份里不含坐标，只带城市名。

别人贡献的菜单包会被清洗。菜名、标签、点评这些外来文本在入库时去掉了尖括号并限制长度，显示时统一转义，页面还有 CSP 策略（脚本只允许从本站加载）。所以就算有人往菜单包里塞脚本，也执行不起来、也没有地址能往外发数据。

认准官方地址：本页所在地址，或仓库 README 里写的那个。仿冒的副本能读走你填在里面的高德 Key。

更完整的说明（威胁模型、漏洞报告方式、已知边界）见仓库的 SECURITY.md。
